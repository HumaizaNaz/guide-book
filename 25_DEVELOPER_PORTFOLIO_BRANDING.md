# Developer Portfolio & Personal Branding
*Recruiter ke pehle filter se guzarna — 2026 reality check ke saath*

---

## Sach Yeh Hai: Portfolio "Job" Nahi Deta

Ek important reality pehle: **portfolio rarely akela job dilata hai.** Employers khud kehte hain — portfolio projects skills seekhne mein help karte hain, lekin screening mein zyada weight nahi rakhte. Job dilata hai: skills + interview performance + network.

**To phir portfolio kyun banayein?** Kyunke woh **filter se bahar hone se bachata hai.** Bina portfolio ke, resume dekhte hi "no relevant experience" keh kar reject ho jate ho. Portfolio ke saath, tumhe ek chance milta hai apna kaam dikhane ka.

---

## PART 1 — KYA DIKHAO (Aur Kya Nahi)

```
✓ Dikhao:
  - 3-4 complete, deployed projects (live link + GitHub)
  - Har project ka "why" — kis problem ko solve kiya
  - Real metrics agar hain (users, performance improvement)
  - Code jo tumne khud likha aur samajhte ho line by line

✗ Mat dikhao:
  - 20 half-finished tutorial clones
  - Copy-pasted boilerplate templates bina customization ke
  - Projects jinke baare mein tum interview mein deep sawaal
    ka jawab nahi de sakte
```

**Rule:** Har second count karta hai. Fluff kaato. Real kaam dikhao. Real stories batao.

---

## PART 2 — PORTFOLIO STRUCTURE (Jo Attention Leta Hai)

```
1. Hero section    — kya karte ho, ek line mein (not "Full Stack Developer",
                      balke "I build AI-powered tools for small businesses")
2. Featured projects — top 3, case-study style (problem → approach → result)
3. GitHub activity   — real, consistent commits (fake green squares kaam nahi karte)
4. About            — thodi personality, generic "passionate developer" nahi
5. Contact          — direct email/LinkedIn, contact form ke peeche mat chhupao
```

---

## PART 3 — CASE STUDY FORMAT (Har Featured Project Ke Liye)

```
Problem:    Kya specific problem solve kiya (1-2 lines)
Approach:   Kaunsi tech/architecture choose ki aur kyun
Challenge:  Ek real obstacle jo aaya aur kaise solve kiya
Result:     Metric ya outcome (users, speed, ya khud ka learning)
Links:      Live demo + GitHub repo (dono zaroori hain)
```

Yeh format interview mein bhi kaam aata hai — jab poochha jaye "apne kisi project ke baare mein batao", tumhare paas already structured jawab hoga.

---

## PART 4 — PERSONAL BRANDING (Portfolio Se Aage)

Portfolio ek static page hai — **branding ek ongoing activity hai.**

```
LinkedIn        — weekly ek post: kya seekha, kya build kiya
                  (recruiters yahan active developers dhoondte hain)
GitHub          — consistent commits, achi README files, pinned repos
                  curate karo (best 6 projects pin karo)
Content         — chhote blog posts / threads apne learnings pe
                  (isse tumhara knowledge visible hota hai)
Community       — Discord/Reddit mein help karo, apna naam establish karo
```

---

## PART 5 — MAINTENANCE (Yeh Bhool Jaate Hain)

```
✗ "Build once and forget" — portfolio purana ho jata hai
✓ Har naye project ke baad update karo
✓ Purane/weak projects hatao jab better mil jaye
✓ Broken links check karo (deployed demos down ho jate hain)
```
